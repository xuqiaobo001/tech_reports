## 三、核心发现

### 3.1 "单元"概念：CCE 文档中不存在

**"单元"不是华为云 CCE 的标准术语。** 在完整的 CCE 文档目录和具体说明页面中，均未出现"单元"这一概念。

"单元"可能出现在以下其他上下文中：

- **单元化架构**：一种微服务架构设计模式（如蚂蚁金服的 LDC 单元化架构）
- **华为云 ServiceStage**：可能使用"微服务单元"等术语
- **客户自定义概念**：客户方案文档中自行定义的组织单位

### 3.2 CCE 实际使用的三个核心概念

CCE 文档中与"Pod"和"副本"相关的概念体系如下：

| 术语 | 英文 | 含义 | 使用场景 |
|------|------|------|---------|
| **Pod** | Pod | Kubernetes 中的**最小调度对象**，封装一个或多个容器 | 技术文档、YAML 定义 |
| **实例** | Instance | CCE 控制台对 Pod 的**界面术语**，"实例数量"即 Pod 数量 | CCE 控制台 UI |
| **副本** | Replica | YAML 中 `spec.replicas` 对应的**运行副本数**，与"实例"同义 | 工作负载定义、YAML 配置 |

## 四、Pod、实例、副本的关系详解

### 4.1 层级关系

```
工作负载 (Workload, 如 Deployment / StatefulSet / DaemonSet)
  │
  └─ spec.replicas = N  ←── "副本数" / 控制台称"实例数量"
       │
       ├─ Pod 1 (实例1)  ←── 可包含 1 个或多个容器
       ├─ Pod 2 (实例2)
       ├─ ...
       └─ Pod N (实例N)
```

### 4.2 关键文档引用

**Pod 的定义：**

> "工作负载是 Kubernetes 对一组 Pod 的抽象模型，用于描述业务的运行载体，一个 Pod 可以封装 1 个或多个容器。"
>
> — 来源：[创建无状态负载（Deployment）](https://support.huaweicloud.com/usermanual-cce/cce_01_0047.html)

**实例与副本的说明：**

> "实例数量：工作负载的实例数量。工作负载可以有一个或多个实例，用户可以设置具体实例个数，默认为 2，可自定义设置为 1。每个工作负载实例都由相同的容器部署而成。设置多个实例主要用于实现高可靠性，当某个实例故障时，工作负载还能正常运行。"
>
> — 来源：[创建无状态负载（Deployment）](https://support.huaweicloud.com/usermanual-cce/cce_01_0047.html)

**副本的 YAML 映射：**

> "replicas: 实例数量。"
>
> "READY：已经部署完毕的 pod 副本数"
>
> — 来源：[创建无状态负载（Deployment）](https://support.huaweicloud.com/usermanual-cce/cce_01_0047.html)

### 4.3 三者等价关系

| 维度 | Pod | 实例 | 副本 |
|------|-----|------|------|
| **本质** | 同一事物 | 同一事物 | 同一事物 |
| **使用场景** | 技术文档、API 交互 | CCE 控制台 UI | YAML 定义、命令行输出 |
| **数量表达** | Pod 数 | 实例数量 | `spec.replicas` |
| **来源** | Kubernetes 原生术语 | 华为云控制台术语 | Kubernetes 规范术语 |

**核心结论：实例 = 副本 = Pod 的运行态**，三者是同一事物在不同上下文中的不同叫法。

## 五、CCE 工作负载类型与 Pod 的关系

CCE 支持多种工作负载类型，每种类型管理 Pod 的方式不同：

| 工作负载类型 | 与 Pod/副本的关系 | 适用场景 |
|-------------|-----------------|---------|
| **无状态负载 (Deployment)** | 通过 `replicas` 管理多个相同 Pod 副本，支持水平伸缩 | Web 应用、微服务 |
| **有状态负载 (StatefulSet)** | 管理有序的 Pod 副本，每个 Pod 有稳定标识 | 数据库、分布式存储 |
| **守护进程集 (DaemonSet)** | 每个节点运行一个 Pod（非按副本数管理） | 日志采集、监控 Agent |
| **普通任务 (Job)** | 运行完成后终止的 Pod | 批处理任务 |
| **定时任务 (CronJob)** | 按计划周期性创建 Job（进而创建 Pod） | 定时备份、报表生成 |

## 六、对解决方案验证的建议

### 6.1 术语一致性检查

在验证客户方案时，需关注：

- 方案文档中是否使用了"单元"等非标准术语，需确认其具体指代
- 不同章节中"实例"、"副本"、"Pod"是否混用导致歧义
- 计费说明中的"实例"与 CCE 控制台的"实例"是否指向同一概念

### 6.2 高可用验证要点

当方案涉及多个 Pod 副本时，需验证：

| 检查项 | 验证要点 |
|--------|---------|
| 副本数设置 | `replicas` 是否满足高可用要求（建议 ≥ 2） |
| 反亲和性配置 | 多副本是否分布在不同节点/可用区 |
| 滚动升级策略 | `maxUnavailable` 和 `maxSurge` 是否合理，避免升级中断服务 |
| 资源限制 | 每个 Pod 是否设置了 `requests` 和 `limits` |
| 健康检查 | 是否配置了 Liveness Probe 和 Readiness Probe |

---

## 七、结论

1. **"单元"不是 CCE 标准术语**，在 CCE 文档中没有对应概念定义。如客户方案中出现该术语，需进一步确认其含义。
2. **Pod、实例、副本三者在 CCE 中本质等价**，分别用于技术文档、控制台 UI、YAML 定义三个不同上下文。
3. **工作负载（Workload）** 是上层抽象，通过 `replicas` 字段控制 Pod/实例/副本的数量，实现业务的高可用和弹性伸缩。
