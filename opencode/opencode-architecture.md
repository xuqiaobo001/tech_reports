# OpenCode 架构分析报告

> 分析日期: 2026-03-25

## 概述

OpenCode 是一个 AI 驱动的开发工具，采用模块化的架构设计，支持 CLI、Web、Desktop 等多种交互方式。本文档详细分析了其代码仓库结构和 CLI 与 Server 的解耦设计。

---

## 1. 整体目录结构

OpenCode 采用 **monorepo** 结构，使用 Turbo 管理多个包：

```
opencode/
├── packages/
│   ├── opencode/      # 核心 CLI + Server
│   ├── console/       # Web 控制台 (SolidJS + Vite)
│   ├── app/           # Web 应用
│   ├── desktop/       # Tauri 桌面应用
│   ├── web/           # Web 界面
│   ├── ui/            # 共享 UI 组件
│   ├── util/          # 工具库
│   ├── sdk/           # JavaScript SDK
│   ├── plugin/        # 插件系统
│   ├── function/      # 函数执行
│   ├── script/        # 脚本系统
│   └── slack/         # Slack 集成
├── sdks/              # 多平台 SDK (VS Code 等)
├── infra/             # 基础设施配置
└── specs/             # API 规范
```

### 核心包说明

| 包名 | 功能描述 |
|------|----------|
| `opencode` | 核心 CLI 和 Server 实现 |
| `console` | Web 控制台，用于可视化管理 |
| `app` | Web 应用入口 |
| `desktop` | Tauri 桌面应用封装 |
| `sdk` | JavaScript SDK，供第三方集成 |
| `plugin` | 插件系统扩展 |

## 4. CLI 与 Server 的解耦设计

### 架构图

```
┌─────────────────┐         HTTP API         ┌─────────────────┐
│      CLI        │ ◄──────────────────────► │     Server      │
│  (用户交互层)    │                          │   (服务层)       │
└─────────────────┘                          └─────────────────┘
        │                                            │
        ▼                                            ▼
  命令解析、UI渲染                            业务逻辑、数据存储
```

### 解耦机制

#### 4.1 明确的边界划分

| 层级 | CLI 职责 | Server 职责 |
|------|----------|-------------|
| 用户交互 | 终端 UI、命令解析 | - |
| 业务逻辑 | - | API 服务、状态管理 |
| 数据存储 | - | SQLite 数据库 |

#### 4.2 依赖注入

- 使用 **Effect** 系统（类似 ZIO）进行依赖管理
- 各服务通过 Layer 提供
- 支持测试时替换实现

#### 4.3 模块化设计

```
核心模块:
├── Agent      # AI 代理
├── Tool       # 工具集成
├── Skill      # 技能系统
├── Provider   # AI 提供商
└── Instance   # 项目实例
```

## 5. 通信和配合方式

### 整体通信架构

```
┌──────────────────────────────────────────────────────────┐
│                      客户端层                             │
│  ┌──────┐  ┌──────┐  ┌──────────┐  ┌─────────┐          │
│  │ CLI  │  │ Web  │  │ Desktop  │  │ VSCode  │  ...     │
│  └──┬───┘  └──┬───┘  └────┬─────┘  └────┬────┘          │
└─────┼─────────┼───────────┼─────────────┼────────────────┘
      │         │           │             │
      ▼         ▼           ▼             ▼
┌──────────────────────────────────────────────────────────┐
│                    HTTP API / SDK                        │
│                   @opencode-ai/sdk                       │
└──────────────────────────┬───────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────┐
│                    Server (Hono)                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ Instance │  │ Session  │  │  Auth    │  ...          │
│  └──────────┘  └──────────┘  └──────────┘               │
└──────────────────────────┬───────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────┐
│              数据层 (SQLite + Drizzle ORM)               │
└──────────────────────────────────────────────────────────┘
```

### 关键通信组件

| 组件 | 功能 |
|------|------|
| **SDK** (`@opencode-ai/sdk`) | HTTP 客户端，封装 API 调用 |
| **Instance** | 项目实例管理，维护目录状态 |
| **Session** | 会话管理，追踪 AI 对话 |
| **Event Bus** | 内部事件通信 |
| **SSE** | Server-Sent Events，支持实时更新 |

### CLI → Server 通信流程

1. CLI 解析用户命令
2. 通过 SDK 构建 HTTP 请求
3. Server 接收请求，处理业务逻辑
4. 返回响应或通过 SSE 推送实时更新
5. CLI 渲染结果到终端

## 8. 架构特点总结

| 特性 | 说明 |
|------|------|
| **模块化设计** | 清晰的功能边界，易于维护和扩展 |
| **多端支持** | 支持 CLI、Web、Desktop 多种交互方式 |
| **AI 驱动** | 深度集成多种 AI 提供商 |
| **插件系统** | 支持自定义技能和工具 |
| **工作区隔离** | 每个项目有独立的状态和管理 |
| **事件驱动** | 异步架构，支持实时更新 |
| **依赖注入** | 使用 Effect 系统，便于测试和扩展 |

---

## 9. 设计优势

1. **独立部署**: CLI 和 Server 可以独立部署和扩展
2. **统一 SDK**: 通过统一的 SDK 支持多种客户端
3. **一致性**: 保持核心业务逻辑的一致性和可测试性
4. **可扩展性**: 模块化设计便于添加新功能
5. **灵活性**: 支持多种使用场景和部署方式
