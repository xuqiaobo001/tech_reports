# 华为云 ModelArts 专属资源池配额限制深度分析

## 1. 核心结论

专属资源池配额是**按账户、按区域**设置的，与工作空间配额是两套独立的管控体系：

- **工作空间配额**：控制消费上限（每个空间最多能用多少资源）
- **资源池配额**：控制物理基础设施上限（整个租户在该 Region 最多能创建多少资源池/实例）

两者互不叠加，互不替代。

## 3. 单个资源池的操作限制

| 限制项 | 约束 | 说明 |
|--------|------|------|
| 单次创建/扩容节点数 | 建议 **≤ 30 个** | 超过可能因流量控制导致创建失败，可分批操作 |
| 实例规格种类 | 最多 **10 种** | 每种规格必须唯一（如 snt9B + snt9C + CPU 算 3 种） |
| 部署服务数 | 实时 + 批量合计 ≤ **50 个** | 每个专属资源池的限制 |
| 容器引擎空间 | 默认 50 GiB | 创建时可自定义，无额外费用 |
| 按机柜购买 | 1 机柜 = 6 节点 | 必须整柜创建或删除，不能单独增减 |
| 节点规格变更 | 不支持 | 已创建的节点不支持变更规格，只能删除重建 |

## 4. 物理资源池 vs 逻辑资源池

### 4.1 物理资源池

物理资源池是实际硬件资源的集合，必须在逻辑池之前创建。

**特性：**
- 独占物理机，提供物理隔离
- 支持三种作业类型：训练（TRAIN）、推理（INFER）、开发环境（DevEnviron）
- 不支持弹性资源扩缩
- 存储配置仅在物理池上可用
- 支持配置网络（VPC、子网、安全组）

### 4.2 逻辑资源池

逻辑资源池从物理资源池中划分出来，可创建多个逻辑子池。

**特性：**
- 支持弹性资源，创建和扩容速度更快
- 可独立设置配额：
  - **保障配额**（Guaranteed）：最小可用资源量（可设为 0）
  - **配额上限**（Limit）：最大可用资源量（必须 ≥ 保障配额，最小值为 1）
- 当保障配额 < 配额上限时，不支持将"DevEnviron"作为作业类型
- 驱动升级需启用节点绑定（需联系华为工程师）

### 4.3 逻辑子池配额示例

```
物理资源池（总容量：64 卡 snt9B）
│
├── 逻辑子池 A（训练池）
│   ├── 保障配额：32 卡
│   ├── 配额上限：48 卡
│   └── 可弹性借用物理池空闲资源（最多到 48 卡）
│
├── 逻辑子池 B（推理池）
│   ├── 保障配额：16 卡
│   ├── 配额上限：32 卡
│   └── 可弹性借用物理池空闲资源（最多到 32 卡）
│
└── 未分配：0 卡（保障配额总和 = 物理池总容量）
    → 32 + 16 = 48 卡已保障，剩余 16 卡按弹性竞争分配
```

## 5. 昇腾实例规格可选范围

### 5.1 规格矩阵

| 规格系列 | 芯片 | 架构 | 每节点典型配置 | 适用场景 |
|----------|------|------|---------------|----------|
| **snt9** | Ascend 910 | x86 / Arm64 | 多卡裸金属服务器 | 大规模分布式训练 |
| **snt9B** | Ascend 910B | Arm64 | 8 PU/节点，32GB/PU，24 核 192GB | LLM 训练与推理 |
| **snt9B23** | Ascend 910B（超节点） | Arm64 (aarch64) | 16 DIE/节点（1 DIE = 1 颗 910 芯片） | LLM 超大规模训练 |
| **snt9C** | Ascend 910C | Arm64 | 支持超节点，支持 HA 冗余 | 高端训练 |
| **snt3P** | Ascend 310P | Arm64 | 支持虚拟化（最多 7 个虚拟实例） | 推理、轻量计算 |

### 5.2 虚拟化（vNPU）支持

| 规格系列 | 训练 vNPU | 推理 vNPU | 虚拟化模板示例 |
|----------|-----------|-----------|---------------|
| **snt9B** | 支持 | 支持 | `vir10_3c_32g`（10 AI Core, 32GB）、`vir05_1c_16g`（5 AI Core, 16GB） |
| **snt3P** | 不支持 | 支持 | `vir04`（4 AI Core, 12GB）、`vir02`（2 AI Core, 6GB）、`vir01`（1 AI Core, 3GB） |

> **注意**：snt9B 上的 vNPU 尚未完全支持所有大模型算子。MindSpore 分布式训练时，每节点必须配满 8 卡，不支持虚拟化切分。

### 5.3 HA 冗余

使用 snt9C 实例规格时可启用高可用（HA）冗余：
- 超节点默认启用 HA
- 包含 1,000 或 2,000 个节点的集群必须启用 HA

## 6. 工作空间配额 vs 资源池配额的关系

### 6.1 两套体系的定位

```
租户在某 Region
│
├── 第一层：资源池配额（账户级，所有工作空间共享）
│   │   控制对象：物理基础设施总量
│   │   限制内容：资源池数 ≤ 15、实例数 ≤ 2048、NPU 需申请
│   │   管理方式：华为云配额系统 + 工单申请
│   │
│   ├── 物理资源池 1（购买的昇腾服务器，64 卡 snt9B）
│   │   ├── 逻辑子池 a（训练，保障 32 卡，上限 48 卡）
│   │   └── 逻辑子池 b（推理，保障 16 卡，上限 32 卡）
│   │
│   └── 物理资源池 2（CPU 池，用于数据处理）
│
├── 第二层：工作空间配额（空间级，按空间独立控制）
│   │   控制对象：每个空间的资源消费上限
│   │   限制内容：训练卡数、训练时长、推理卡数、推理时长（13 项）
│   │   管理方式：ModelArts 控制台或 UpdateWorkspaceQuotas API
│   │
│   ├── 工作空间 X（PUBLIC）
│   │   ├── 训练 GPU 卡数配额：≤ 40
│   │   ├── 推理 GPU 卡数配额：≤ 24
│   │   └── 关联：逻辑子池 a + 逻辑子池 b
│   │
│   └── 工作空间 Y（INTERNAL）
│       ├── 训练 GPU 卡数配额：≤ 30
│       └── 关联：逻辑子池 a
```

### 6.2 两者的关键区别

| 对比维度 | 工作空间配额 | 资源池配额 |
|----------|------------|-----------|
| **管控层面** | 消费上限（能用多少） | 物理上限（能建多少） |
| **作用范围** | 单个工作空间 | 整个租户在某个 Region |
| **配额粒度** | 训练/推理的卡数和时长 | 资源池数、实例数、核数、内存 |
| **是否可超配** | 多个空间配额之和可超过物理资源 | 不可超过物理上限 |
| **超配后果** | 被物理资源限制（排队等待） | 直接创建失败 |

### 6.3 专属资源池卡数是否等于训练卡 + 推理卡？

**不是。** 三者的关系是：

1. **专属资源池卡数** = 你实际购买的物理服务器上的 NPU/GPU 总量（物理限制）
2. **工作空间训练卡配额** = 该空间内训练作业最多能同时使用多少卡（逻辑限制）
3. **工作空间推理卡配额** = 该空间内推理服务最多能同时使用多少卡（逻辑限制）

训练卡配额 + 推理卡配额 **可以** 超过物理资源池的总卡数，但实际运行时受物理资源限制。这是为了允许"训练和推理分时复用"——白天推理多、夜间训练多。

## 7. 配额申请与提升流程

### 7.1 通用配额提升

```
华为云控制台
    → 服务列表 → ModelArts
    → 配额管理
    → 申请配额
    → 填写所需配额值 + 使用理由
    → 提交审核（通常 1-2 个工作日）
```

### 7.2 昇腾 NPU 特殊流程

```
联系客户经理（优先）
    或
提交服务工单
    → 说明：需要使用的 Region、NPU 型号（snt9B/snt9C）、数量
    → 审批时间：1-3 个工作日
    → 开通后即可在配额内创建资源池
```

### 7.3 资源池数量提升

默认 15 个池，通过工单最多可提升至 50 个。超过 50 个需特殊审批。

## 8. 选型与规划建议

### 8.1 典型场景规划

| 场景 | 推荐配置 | 配额注意事项 |
|------|----------|-------------|
| **小团队 LLM 训练** | 1 个物理池（snt9B × 4 节点 = 32 卡） | NPU 需提前申请；1 个逻辑池即可 |
| **训练 + 推理混合** | 1 个物理池 + 2 个逻辑子池 | 训练池保障配额 60%，推理池保障配额 30%，预留弹性空间 |
| **多团队共享** | 1 个物理池 + N 个逻辑子池（按团队划分） | 工作空间配额控制每团队用量；逻辑子池做物理隔离 |
| **大规模集群** | 多个物理池（按机柜购买） | 单次创建 ≤ 30 节点，分批操作；1000+ 节点必须启用 HA |

### 8.2 常见坑点

1. **昇腾配额为 0**：最常见的问题。必须先申请 NPU 配额，否则无法创建任何昇腾资源池
2. **分批创建**：单次创建超过 30 节点可能失败，需分批操作
3. **机柜锁定**：按机柜购买时，6 节点必须同时创建/删除
4. **规格不可变**：已创建的节点不支持规格变更，只能删除重建
5. **逻辑池 HA 限制**：保障配额 < 配额上限时，不支持开发环境作业类型
6. **包月资源包不可用**：包月/包年资源包只能用于公共资源池，不能用于专属资源池
